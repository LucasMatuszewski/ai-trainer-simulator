2. **High - equipment use cannot complete in production, and NPC purposeful use is unwired.** The E-key path at `src/main.ts:413-425` calls `usePoint`, which creates a `reserved` action (`src/engine/interaction-points.ts:258-274`). Only `activateAction` changes it to `in-use` (`src/engine/interaction-points.ts:279-286`), and the production code never calls that function; `updateInteractionPoints` at `src/engine/interaction-points.ts:299-304` only times out reserved actions. The completion listener at `src/main.ts:602-610` can never apply coffee's caffeine effect. `suggestNpcUse` (`src/engine/interaction-points.ts:460`) also has no production caller, so there is no judgment-driven walk/use/return sequence required by AC-22.

3. **High - NPC needs neither decay at the intended rate nor steer action.** `src/main.ts:1759` passes `dt / 60` to `decayNeeds`, although the function expects in-game minutes and one real second equals one in-game minute (`src/game/npc-needs.ts:58-66`). The world-tick projection at `src/engine/world-tick.ts:323-333` contains no needs or action questions, so even corrected needs cannot influence a Jev choice or trigger purposeful equipment use.

4. **Medium - world-tick repeatedly judges the same next-period destination.** Production supplies every NPC on every tick (`src/main.ts:260`), and `src/engine/world-tick.ts:387-405` adds a destination question for each without checking existing `destMemos`. At a six-second cadence this rejudges each NPC roughly 20-30 times per period and overwrites the prior unconsumed answer at `src/engine/world-tick.ts:574`. This adds cost and makes a pre-decided destination change solely because another identical tick ran.

5. **Medium - a closed dialogue can write stale steering into a later session.** `src/ui/dialogue.ts:261-274` closes by clearing `v2` but does not cancel or fence `steerCurrentTurn`'s promise; its completion callback at `src/ui/dialogue.ts:628-630` renders any new `v2` conversation. `resetSession` only clears the memo (`src/jev/dialogue-wrapper.ts:335`), while an in-flight `steerTurn` later writes to it (`src/jev/dialogue-wrapper.ts:322`). Closing mid-request, then reopening the same NPC/topic can therefore apply the previous session's answer to the new session and rerender it unexpectedly.

6. **Medium - malformed exchange IDs can select candidate zero.** `src/engine/world-tick.ts:502-507` strips an assumed `exchange:${poolId}:` prefix without validating it. A response ID of `"anything"` or `"exchange:wrong:0"` yields `Number("") === 0` after the slice and passes the range check, so an invalid subject answer is logged as applied and steers to the first exchange. Validate exact membership in the candidate IDs sent for that question.
