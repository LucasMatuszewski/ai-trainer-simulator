## Findings

1. **MAJOR — `src/game/events.ts:86-87`: a steered `null` destination is silently discarded.**
   `jevDecisionHooks.pickRandomDestination?.(npcId, period) ?? destinationHooks.pickRandomDestination(npcId, period)` conflates "no hook installed" with "hook installed and returned null" — but `null` ("stay at the desk") is a documented legitimate steered answer (contracts.ts:152-157, and the legacy picker returns null ~90% of the time). A destination wrapper that falls back to the preserved legacy picker (D-47) would return null most of the time, so this line would neutralize destination steering almost entirely: every null answer triggers a hidden extra legacy roll instead. Latent today (no hook installed; default behavior provably unchanged), but it is a contract break in the delivered seam and WS4 will build on it. **Fix (one line, matching the controller resolvers' pattern):**
   ```ts
   const hook = jevDecisionHooks.pickRandomDestination;
   const dest = hook ? hook(npcId, period) : destinationHooks.pickRandomDestination(npcId, period);
   ```
2. **MAJOR (test gap) — the events.ts destination resolution has zero test coverage.** No test imports `runPeriodEvent`/`registerNpcController`; all 17 new tests cover the controller surfaces — and finding 1 lives in the only untested seam call site. **Fix:** one vitest test that registers a stub controller (`registerNpcController` is exported), installs `pickRandomDestination: () => null` on the holder, calls `runPeriodEvent(hud, "afternoon")`, and asserts `setOverride` received `null` (not a legacy roll). This test fails red against the current code — it would have caught finding 1.
3. **MINOR — scope/report contradiction on `src/game/events.ts`.** events.ts is NOT in the WS0 brief's allowed file set, yet it is modified. The delegate's report (deviation #1) says the site "could NOT be wired" and defers to "a one-line orchestrator patch when wiring", and the freshly written comments still describe it as unwired (`npc-controller.ts:495-500` "has no resolver here… outside the WS0 file set"; `npc-controller.ts:425-427` "when it grows its wrapper"). Either the orchestrator applied the patch after the report (then the report and both comments are stale and must be refreshed before commit) or the delegate overstepped its file set and misreported. The wiring itself is behavior-preserving; do not commit it with documentation that says the opposite.
4. **MINOR — no throw containment at the seam.** The resolvers call hooks unguarded; a throwing hook propagates through `controller.update()` into the frame loop (judge point 2's "no hook can throw into the frame loop uncaught" does not hold at the seam). ADR §3.8 assigns try/validate/apply/fallback to the steered wrappers, so this is defensible as-designed — but the invariant is stated nowhere. **Fix:** either wrap the hook call in try/catch falling back to `defaultHooks` (defense in depth), or state the invariant in the `jevDecisionHooks` doc comment ("hooks must never throw; the steered wrapper owns error containment") plus a test.
5. **MINOR — cross-session holder leakage.** `jevDecisionHooks` is a module-global that nothing clears on day-end/reset/restart; live-read prevents staleness within a controller's life, but a hook installed in one session persists into the next unless the installing wave removes it. WS0 installs nothing (no current impact). **Fix:** when the first real wave lands, require `finally`-cleanup (as the holder test does) or add a `resetJevDecisionHooks()` helper.
6. **NIT — `tests/unit/content/npc-content-registry.test.ts:74-97`:** the six-member `DecisionHooks` pin is enforced only by tsc (vitest's esbuild transform does not typecheck); the runtime assertions (`key in none` on `{}`, key count) would pass after a member rename. It holds because tsconfig `include: ["tests"]` makes `pnpm typecheck` cover the test file — worth a one-line comment, not a change.
