## Findings

- **Major - the second day's greeting prefetch is lost.** `src/main.ts:832-836` starts prefetch as soon as the store advances to a new day, while the *old* wrapper is still installed. `endDay()` then calls `startOffice()` on Continue (`src/main.ts:1092-1115`), which replaces the wrapper (`src/main.ts:431-438`) but leaves `lastGreetingPrefetchDay` equal to that day. The new wrapper's memo is empty, so the guard suppresses its prefetch for the entire day. With Jev configured, day-2 greetings take its fallback rather than the chosen lines. Reset the guard or retain/prefetch the new wrapper on each office mount, with a day-transition integration test.
- **Major - Wave 1's `?jev=off|shadow` modes are absent.** WS1 explicitly includes both URL modes (`docs/plans/2026-09-28-jev-parallel-implementation.md:77-91`), and TAC-01 requires `?jev=off` behavior (`docs/ADR/0009-jev-npc-decision-steering.md:564`). No production source reads the `jev` query parameter; `src/main.ts:431-438` always installs the wrapper when a key/proxy exists, and `src/jev/greeting-wrapper.ts:142-185` sends a request when configured. Consequently `?jev=off` cannot prove legacy equivalence and `?jev=shadow` cannot log without applying.
- **Major - enabling Jev after entering the office cannot activate greetings.** `src/jev/greeting-wrapper.ts:261-265` makes `install()` a no-op while unconfigured, and `src/main.ts:431-438` calls it only during office construction. The resolving client can observe a later key (`src/jev/client.ts:41-49`), but the hook is never installed afterward. The settings component is also not mounted by any production source (`src/ui/jev-settings.ts:27-30`; its only call sites are unit tests), so the Wave 1 BYO mode has no in-game entry point. Wire settings to the game and re-install/prefetch on configuration changes.
- **Major - the WS9a browser test does not prove NPC rerouting.** `tests/e2e/ws9a-robot-collision.spec.ts:90-111,131-136` samples all NPCs while the robot walks but never arranges an NPC route across the robot, asserts one approaches it, or observes a detour. The distance check passes even if every NPC stays far away. The unit test checks routing, but the WS9a Done line specifically requires a nearby NPC to route around the robot in Playwright (`docs/plans/2026-09-28-jev-parallel-implementation.md:206-207`).
- **Minor - the social persistence test passes without persistence.** `tests/unit/game/social-actions.test.ts:130-139` asserts only in-memory state after dispatch, despite its `dispatch+save+load` title. In the fresh run, `localStorage` was undefined and `GameStore.save()` logged `Failed to save game`, caught by `src/game/state.ts:72-83`; the test still passed. Use a storage-backed store/browser test and assert the serialized v2 social state survives reload.
